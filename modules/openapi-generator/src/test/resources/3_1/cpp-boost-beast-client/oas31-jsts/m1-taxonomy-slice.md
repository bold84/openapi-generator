# Wave-M1 slice: typed-mapping taxonomy probe (GM1 operational definitions)

Slice commit: `6609fe51228`.

## Method

`mprofile/m-probe-schemas.yaml` (11 destination-domain models: int32/int64/
float/double/string/bool/enum/nullable-tristate/AnyType/variant/collections)
generated by the current CLI (`packageName=…,apiPackage=api,modelPackage=model`
→ flat `namespace model` emission, matching the Gate A surface); 55 probe
cases compiled into `mprofile/m_probe_driver.cpp` (-Wall -Wextra -Werror,
Boost.JSON header-only): parse → GENERATED `fromJsonValue_X` → re-encode via
the GENERATED `toJsonValue` axis → compare with `oas31::deepJsonValueEqual`
(the exact number-aware comparator: 1 == 1.0, all numbers via ExactNumber).
Exception classification keyed on the observed message text.

## Pinned taxonomy (operational definitions for GM1)

| Class | Operational marker (this generator) |
| --- | --- |
| `transportParseError` | `boost::json::parse` throws (malformed JSON only). NOTE: non-finite literals DO parse (1e400 → +inf, serializes as `1e99999`); big integers > uint64 parse as lossy `double`; 30-digit decimals parse as shortest-round-trip doubles — the exact value is recoverable only via the oas31 lexeme layer (M2). |
| `schemaInvalid` | Decode failure with validator/type language: "Value not allowed" (enum), "value is not a string/boolean", "Required field 'kind' not found", "No matching branch" / "More than one matching branch" (variant), "Decode failed for '<p>' … not a number" (wrong kind into numeric destination — semantically a type mismatch; message = converter wording). |
| `unrepresentable` | Decode failure "Decode failed for '<p>' in <M>: **not exact** [to_number]" — int32/int64 range failures THROW (no silent truncation). Non-finite/oversized numbers (1e400, 2^64) → inf or lossy double at parse: unrepresentable per the lexeme (their mathematical value differs from the stored kind). |
| `representable` | Decode ok AND `deepJsonValueEqual(reencoded, input)` — exact mathematical round trip. |
| `narrowed-representable` (float domain only) | Decode ok; re-encoded value = the destination's nearest value ≠ input for >7 significant digits (0.1 → `1.0000000149011612E-1`); IDEMPOTENT (re-decode of the re-encoded value is stable). Overflow beyond FLT_MAX (3.4028236e38) converts to +inf SILENTLY — a GM2 diagnostic gap (M2 fixes with a finite-check). |

## Findings (F1–F9)

- **F1** int32/int64 out-of-range → throwing representation error ("not
  exact"), message-identifiable. `int32-overflow`, `int32-underflow`,
  `int64-overflow`, `int64-uint64-max`, `int64-2pow64`: `representation-error`
  ✓ no silent truncation.
- **F2** numeric kind mismatch (string→int32) → "not a number" (converter
  wording) — semantically schema-invalid; M2 validator-first classification.
- **F3** float domain = 24-bit mantissa: 0.1/pi(20) narrow (idempotent);
  float > FLT_MAX → silent `+inf` (F3 = M2 finite-check fix); re-encode emits
  the exact float value as double.
- **F4** double domain = exact for finite values (0.1 re-encodes as `0.1`;
  max/min-normal exact). Non-finite literals (1e309/1e400) → +inf at parse
  (raw also shows `1e99999` serialization) — M2 lexeme check for the
  unrepresentable class.
- **F5** integers > uint64 (2^64, 2^70) parse as `double` (precision lost at
  16 digits) — lexeme-recoverable; M2 pin.
- **F6** OAS 3.1 `nullable: true` is NOT a 2020-12 keyword → `type: string`
  + null instance = schema-invalid (CORRECT semantics). 3.1 type-array
  `[string,"null"]` → `NullableField` tri-state: null/missing/value all
  round-trip EXACTLY.
- **F7** enum: destination = `std::string`; closed set ENFORCED at decode
  ("Value not allowed") — open-value policy = validator-enforced, member
  type open (string).
- **F8** oneOf variant with discriminator: exclusive branches (required
  meow/bark) round-trip exactly; unknown/missing discriminator kind =
  schema-invalid ("No matching branch").
- **F9** parser: duplicate keys → last-wins; `-0` → 0 (sign lost);
  unknown object properties are dropped on re-encode (schema-declared
  members only); deep arrays parse fine (32 levels).

## Consequences for M2/M3 (design commitments)

1. M corpus rows map onto this table; every class ≥ 5 rows; the
   float/double boundary rows carry the F3/F4/F5 policy.
2. M2 driver: two-phase classification (S-V validator FIRST via the
   validator surface, then the representability gate) so F2 rows classify
   schemaInvalid and F1 rows unrepresentable by VALIDATOR behavior, not
   message matching alone.
3. M2 converter fixes: float decode finite-check (F3) — non-finite
   destination = representation diagnostic; the 1e400/2^64 classes get the
   lexeme-based unrepresentable detection (F4/F5).
4. GM3 doc: destination-domain table = this probe's observed behavior
   (float = narrowed-idempotent documented domain; double = exact-finite;
   ints = throwing representation errors).
